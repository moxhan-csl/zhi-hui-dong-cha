| 级别 | 判据 |

| 高 | 会导致错误结论、数据污染、越权/凭据暴露、真金白银损失，或让运维做出误判 |

三条约定：

1. **每条必须给得出 `文件:行号`**。行号随改动漂移，符号名不会——所以同时给符号名。

## 4. 一条建议先立住的通用原则

**任何降级都必须在响应体里带 `degraded` 标记**（或等价字段），前端才有地方显示，运维才有地方告警。

本清单里 D-14（假向量入库）、D-28（评测跑在降级窗口）、D-32（成本超阈值只回显）、pgvector 内存回退四处，都是同一个模式的实例：**系统知道自己在降级，用户和运维不知道**。先立原则，再逐条改，比一条条打补丁省。

按这条原则的进度：**D-32（第一批）** 补上了拦截与消费点；**D-14（第五批）** 没有走"加标记"而是更进一步——直接拒绝写假向量，要写必须显式开 `app.llm.allow-hash-vectors` 并接受一条 WARN（第六批把 compose 透传与文档口径补齐）；**D-28（第六批）** 走的是原则本身——`EvalRun.env` 里带 `vectorStore`/`embedMode`/`degraded` 落库并在前端回显，同时整轮改成严格检索，降级窗口跑出的分数不再有机会被当成可比数据；仍开放的只有 **pgvector 内存回退**（`vectorStore` 字段有如实上报，评测的 env 快照也带它，但**问答结果本身**不带"这次是内存检索"的标记）。

## 6. 明确不建议做的

- 换掉 WebFlux 或退回阻塞栈——编排方式是对的（Controller 侧 `boundedElastic` 包装正确，过滤器读的是内存镜像不阻塞），缺的只是配额和池子容量。**第八批之后这条更要紧**：业务表镜像改直读让读路径真的落到 MySQL，事件循环上但凡留一次 DB 往返就不再是"读内存不阻塞"的假象（本批把仅剩的两处 `ChatService.stream` / `DocumentController.upload` 挪进了 deferred 链，`AuthWebFilter` 与 `/api/health` 刻意保持零 I/O）。
- 调大 PG 连接池 6——瓶颈在 LLM 往返（120s 超时），不在它。
- 先补单元测试——`pom.xml:96` 挂着 `spring-boot-starter-test` 却零测试。真要补，先补**鉴权矩阵**和**读写一致性**（第八批前叫"镜像一致性"）两处的集成测试，那才兜得住 D-30/D-34；给 UI 和 prompt 补单测是投入产出比最差的方向。
- 把"手册里有但代码里没有"的能力写回设计（LangChain4j 编排、MinIO、RabbitMQ、Prometheus/Grafana、SSO 等）——清单见设计文档 §12.1，那些是边界，不是待办。
- **给共享生产库补 UNIQUE 约束**，或给集合表（`kb_members`/`conversation_kb_ids`）的外键列再声明一份显式索引——前者会让存量脏数据上的写入直接失败，并把"业务唯一性"这种语义判断交给数据库（第九批的取舍是代码层拒绝，代价如实写在 §5.9：非原子）；后者 InnoDB 建外键约束时已自动为外键列建索引，再加一份只是同列重复索引。要核对索引存在与否，用 `SHOW INDEX` 或 `information_schema.statistics`，**不要凭注解里有没有写来判断库里有什么**。
